# BuhCRM

Небольшой веб-инструмент для задач бухгалтерской команды: клиенты, отделы, исполнители, календарь, повторяющиеся задачи и история действий. Разрабатывался для одной организации и нескольких сотрудников. Поддерживает несколько организаций и системного администратора.

Python 3.12, FastAPI, Jinja2, SQLAlchemy 2, PostgreSQL 16 и Alembic. Исходники выделены из действующего проекта; клиентские данные, серверные конфигурации и рабочие учётные данные в репозиторий не входят.

## Запуск

Нужны Python 3.12 и отдельная PostgreSQL 16 база в UTF-8. Пользователь приложения должен владеть этой базой. Не используйте существующую рабочую БД для знакомства с проектом.

Пример подготовки PostgreSQL в Linux:

```sh
sudo -u postgres createuser --pwprompt buhcrm
sudo -u postgres createdb --owner=buhcrm --encoding=UTF8 --template=template0 buhcrm
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python -c 'import secrets; print(secrets.token_hex(32))'
```

В `.env` укажите URL своей базы и пароль созданной роли; сгенерированное значение запишите в `SECRET_KEY`. Если пароль содержит специальные символы, закодируйте их для URL. Затем:

```sh
alembic upgrade head
python -m app.cli create-organization --inn 0000000000 --name "Тестовая организация" \
  --admin-email admin@example.invalid --admin-name "Администратор"
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

CLI запросит новый пароль дважды без отображения. После запуска откройте <http://127.0.0.1:8000/login>. Для системного администратора предусмотрена команда `python -m app.cli create-admin --email admin@example.invalid --name "Администратор"` с другим, ещё не занятым email.

Приложение и Alembic читают `.env` из корня проекта. Унаследованная схема миграций исправлена для установки на пустую БД. Настройка `search_path=app,public` поддерживается для существующих установок; новая установка может использовать стандартную схему `public`.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Обязательный SQLAlchemy URL своей PostgreSQL-базы |
| `SECRET_KEY` | Обязательный случайный секрет сессий |
| `ENV` | Метка экземпляра, например `dev`, `production`, `clone` |
| `CLONE_MODE` | Отметка тестового контура, отдельная cookie по умолчанию и отключение внешних интеграций |
| `SESSION_COOKIE_NAME` | Собственное имя cookie, если несколько экземпляров используются рядом |
| `COOKIE_SECURE` | `true` для передачи cookie только по HTTPS |
| `DISABLE_EXTERNAL_INTEGRATIONS` | Отключает серверные обращения к внешним интеграциям; в примере включено |
| `DADATA_API_TOKEN` | Необязательный токен Dadata для поиска организации по ИНН |

Ручное создание первоначальной организации через CLI не требует Dadata. Регистрация через веб и поиск по ИНН требуют включённой интеграции и собственного токена. Незавершённый исторический почтовый обработчик в эту версию не включён.

При развёртывании клона используйте отдельные БД, роль, секрет и cookie. `CLONE_MODE` отключает интеграции, но сам по себе не является сетевым экраном. При необходимости запретите исходящие соединения на уровне контейнера или службы. Для публикации приложения в интернете отдельно нужны HTTPS и настройка обратного прокси; не включайте доверие к произвольным proxy-заголовкам.

## Проверки

Для интеграционных тестов подготовьте **отдельную пустую тестовую БД**. Укажите её URL в `TEST_DATABASE_URL`:

```sh
TEST_DATABASE_URL='postgresql+psycopg://buhcrm:CHANGE_ME@127.0.0.1:5432/buhcrm_test' \
  python -m unittest discover -s tests -v
```

Тесты откажутся использовать URL обычной базы приложения. Они запускают миграции в тестовой базе и проверяют формы и конкурентное завершение повторяющейся задачи через HTTP. Не направляйте тесты на базы с нужными данными.

## Состояние проекта

Первый проход исправлений устраняет дубли маршрутов и авторизации, скрываемые ошибки загрузки разделов, ошибки установки с нуля, обработку некорректных дат, перенос срока без проверки исполнителя, внешний переход после входа и одновременное создание нескольких повторов одной задачи. Журнал входов с привязкой к пользователям пока не реализован.

Следующий этап — единые правила видимости и действий с задачами для отделов и исполнителей, защита всех изменяющих форм от CSRF и согласованная работа с часовыми поясами. До этого версия предназначена прежде всего для доверенного внутреннего контура. Описанное состояние не означает, что завершён полный аудит безопасности.
